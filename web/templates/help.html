Grammars

The home page lists all grammars available in this installation. Click any row to select that grammar; the navigation bar will then give access to its pages. The table shows:

Grammar
Human-readable name of the grammar.
File
The .db filename. The name encodes the grammar and version, e.g. ERG_2025.db.
Lexicon
Total number of lexical entries (including generic entries used for unknown words).
Rules
Total number of phrase-structure and lexical rules.
Trees
Number of treebanked sentences available for browsing. Grammars without a treebank show nothing here.
License
The distribution licence for the grammar.
Website
Link to the grammar project's home page.

Use the DataTable's Filter box to search by name or filename, and click any column header to sort.

Grammar Summary

The grammar summary page (reached via the grammar name in the navigation bar) shows three tables.

Grammar Metadata

Administrative information stored in the grammar: full name, version, language, maintainer contact, licence, website, and so on.

Grammar Summary

A count of every object type defined in the grammar, split into two columns:

  • # in Grammar — total number defined in the TDL source.
  • # in Tree Bank — how many of those were actually used in at least one treebanked parse.

Object types include: lex-type (lexical types), lex-entry (individual lexemes), rule (phrase-structure rules), lex-rule (lexical/morphological rules), root (root conditions), and plain type (all other types in the hierarchy).

Treebank Summary

Coverage statistics for the attached treebank: number of profiles (corpora), distinct sentences, and total word tokens.

Rules

The Rules page lists all phrase-structure rules, lexical rules, and root conditions defined in the grammar. Columns:

Rule
The TDL identifier. Click to open the type page for that rule.
Type
The parent type the rule inherits from. Click to open its type page.
Name
Long name or description, if provided in the grammar documentation.
Status
rule — phrase-structure rule (combines two or more daughters).
lex-rule — lexical or morphological rule (applies to a single lexical sign).
root — root condition (constrains what counts as a complete parse).
Frequency
Number of times this rule was used in the treebank. Zero means the rule exists in the grammar but was never selected in a gold parse.
Arity/Head
Number of daughters the rule takes, and which daughter is the head.

The table is sortable and filterable via DataTables.

Lexical Types

The Lexical Types page lists all lexical types — the types that lexical entries instantiate. Columns:

Lexical Type
The TDL identifier. Click to open the type page, which shows all lexemes of this type and example sentences.
Name
Long name or description from the grammar documentation.
Lex Freq
Number of lexical entries of this type.
Corpus Freq
Number of times any lexeme of this type was used in a treebanked parse.
Words
A sample of the most frequent words of this type.

Type Page

Every identifier in the grammar — types, lexical entries, rules — has its own page, reached by clicking its name anywhere in the interface or by searching for it. What is shown depends on the status of the type.

All types
  • Parents / Children — immediate supertypes and subtypes in the type hierarchy; each is a link to its own page.
  • TDL — the full type definition from the grammar source, with syntax highlighting. Type names within the TDL are clickable links.
  • Source — the file and line number where the type is defined.
Lexical types (lex-type)

Shows a table of all lexemes of this type (lexeme identifier and treebank frequency) with the word-forms they appear as, followed by a sample of treebanked sentences in which any of those lexemes was used. The relevant word in each sentence is highlighted in green.

Lexical entries (lex-entry, generic-lex-entry)

Shows the word-forms for this specific lexeme and a sample of sentences in which it appears.

Rules and roots (rule, lex-rule, root)

Shows a sample of treebanked sentences in which this rule or root condition was applied. The span covered by the rule is highlighted.

Sentence visualisations

For each example sentence, up to four views can be toggled on/off with buttons:

Tree
The derivation tree from the treebank: the sequence of grammar rules and lexical entries that produced the parse.
MRS
Minimal Recursion Semantics — the flat semantic representation. Variables are colour-highlighted; hovering shows their properties (tense, number, etc.).
DMRS
Dependency MRS — a graph view of the same semantics. Nodes are predicates; edges are argument relations. Clicking a node highlights its dependents.
[MRS]
The raw MRS string as stored in the treebank.

Search

The search box in the navigation bar accepts any of:

  • Lemma / word-form — finds lexical entries whose orthography matches. Supports * as a wildcard (e.g. run*).
  • Type name — finds any type in the hierarchy (including rules, lexical types, and plain types). Wildcards supported.
  • Predicate — finds lexical entries by their MRS predicate symbol (e.g. _run_v_1). Wildcards supported.

Results are grouped by category. Click any result to open its type page.

Demo

The Demo page lets you parse sentences interactively using ACE and the selected grammar's compiled .dat file. It is only available for grammars that have been compiled with ACE (see the installation guide).

Controls
Input sentence
Type a sentence or choose from the history (shown in the dropdown). The × button clears the field so all history entries are listed.
Grammar
Choose which compiled grammar to parse with. Only grammars with a .dat file are listed.
Results
Maximum number of parses to return (1–10).
Zoom
Scale the visualisations to 100%, 75%, or 50%.
Tree / MRS / DMRS
Checkboxes to choose which representations to request.
Results

Each parse is shown in a card. The Tree button (active by default) shows the derivation tree. MRS and DMRS are rendered on first click (lazy rendering). The Generate button sends the MRS back to ACE to produce surface realisations — useful for checking the semantics round-trips correctly.

Your parse history is stored in the browser (localStorage) per grammar, initialised from the grammar's example sentences on first visit, and capped at 20 entries.

Background

DELPH-IN (delph-in.github.io) grammars are large-scale, precision grammars for natural language processing written in the Type Description Language (TDL). They produce detailed syntactic and semantic analyses and are used in both parsing and generation. Examples include the English Resource Grammar (ERG), Jacy (Japanese), GG (German), and many others.

Semantic representations use Minimal Recursion Semantics (MRS), a flat, underspecified formalism that avoids committing to a single scope reading while remaining computationally tractable. DMRS (Dependency MRS) is a graph-based equivalent.

Treebanks attached to a grammar are collections of sentences for which a human annotator has selected the correct parse from the grammar's output. Frequency counts throughout LTDB refer to these gold-standard selections.
